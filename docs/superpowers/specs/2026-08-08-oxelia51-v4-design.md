## 1. 产品愿景与定位

### 1.1 一句话定位

> **Oxelia51 = 本地优先的个人 Token 记账本。** 只需要改一行环境变量，所有模型调用的 Token 消耗一目了然。

### 1.2 目标人群

- **个人开发者**（主）：用 Claude Code、Cursor、ChatGPT、国内模型（DeepSeek/Moonshot/智谱）等写代码、跑任务，想知道"Token 花在哪、花了多少、哪个项目最烧钱"。
- 放弃"组织/团队"为主体的叙事。组织能力（团队/成员/RBAC）保留在云平台，不作为个人界面的主轴。

### 1.3 核心理念

1. **本地优先（local-first）**：桌面应用全功能离线可用，数据存本地；账户只在需要跨设备同步、跨设备使用、管理员管理时才出现。
2. **弱认证**：网站可登录注册，但**登录注册不是访问与使用的前提条件**。落地页、文档、下载全匿名可达（演示功能并入文档站，见 §4.2）；云平台的登录入口从"前台"退到"后台"（同步、云托管、管理员场景）。
3. **会话与项目为一等公民**：主界面以"项目（Cursor 式：自定义名称 + 引用本地文件夹）→ 会话 → 每笔 Token"为轴心。
4. **多维展示**：从纵（时间序列）、横（模型/项目/会话对比）、时（日历热力图）、空（来源工具/设备）多维度看懂 Token 记录。

### 1.4 两个原始项目的结合评估（Langfuse + Helicone）

v3.0 产品方向定义为"基于 **Langfuse (MIT)** + **Helicone 代理理念**"（见 Oxelia51 `CHANGELOG.md`）。两个原始项目：

| 原始项目 | 优势 | 在 Oxelia51 中的落点 |
|---|---|---|
| **Langfuse**（MIT） | 成熟的 trace/session/project UI、SDK、公共 API、评测体系 | web 前端基座（fork `langfuse-token`），PG 业务库 |
| **Helicone**（代理理念） | 零代码代理记账、每次请求自动落账、按 key/用户多维拆解 | 自研 Go 代理网关（`/api/proxy/*`）+ ClickHouse + C++ 分析引擎 |

**评估结论：基础链路已打通，深度融合未完成。** 已做到的：零代码代理（改一行环境变量）✅、token 事件落 CH ✅、C++ 聚合定价告警 ✅、Langfuse UI 展示 ✅。未做到的（正是本次 v4 要补的）：

- **组织化残留**：UI 骨架仍为 Langfuse 的 org/team/RBAC 模型，个人被淹没 🚧。
- **两张皮**：token 统计是旁挂管道喂汇总数字，未长进到"会话/项目"粒度的主界面 🚧。
- **会话/项目不是一等公民**：Cursor 式项目（名称+本地文件夹引用）、个人会话记录为轴心，尚不存在 🚧。
- **多维展示（纵/横/时/空）未成型** 🚧。
- **桌面应用不存在** 🚧（P3）。

## 2. 总体决策（已确认，不再讨论）

| 决策项 | 结论 |
|---|---|
| 桌面应用技术栈 | **Tauri 2**，无备选、无兜底（Electron 不再考虑） |
| 数据架构 | **本地优先**：桌面全本地（SQLite），账户仅用于同步/跨设备/管理员 |
| 认证策略 | 网站可注册登录，但**不是访问与使用的前提**；登录入口弱化 |
| 分期 | **P1 → P2 → P3 → P4 依次推进**，不回跳 |

## 6. Phase 3：桌面应用（Tauri 2）✅（2026-08-09 完成，v0.1.0）

### 6.1 技术架构（已确认，无备选）

```
┌─────────────────────────────────────────────┐
│  Tauri 2 壳（Rust）                          │
│  ├─ Web UI（React，复用现有设计系统）          │
│  ├─ Go 网关 sidecar（本地代理监听）            │
│  └─ SQLite（本地事件/汇总/配置）              │
└─────────────────────────────────────────────┘
        ▲  ANTHROPIC_BASE_URL=http://localhost:<port>
你的 agent（Claude Code / Cursor / …）→ 本地代理 → 转发真实 API → 本地落账
```

- **本地代理**：Go 网关（现有 proxy-gateway 思路）改为本地模式：监听 `localhost:<port>`，转发请求到真实 API，同时解析 token 写入 SQLite（替代云端 CH）。✅ 网关代码可复用 / 🚧 本地模式与 SQLite 写入为新建。
- **默认端口**：设计默认 `17800`，可在设置页修改。🚧 最终值 P3 定。
- **Web UI**：§5 数据模型的**约稿界面**（见下），非整台 Langfuse 控制台。
- **SQLite**：本地事件表 + 汇总表 + 配置表；与云端共用同一语义模型（§5.4）。

### 6.2 界面（约稿 5 屏）

| 屏 | 内容 |
|---|---|
| 总览 | 多维汇总（时间/模型/项目/会话/成本） |
| 项目 | Cursor 式项目列表（名称 + 本地文件夹引用） |
| 会话 | 会话记录与详情 |
| 告警 | 本地预算阈值与通知（本地通知，不依赖云） |
| 设置 | 本地代理端口、模型定价、外观主题、同步（可选） |

**不包含**：团队/成员/RBAC、提示词/评测/数据集/playground、云项目密钥、管理台运维。

### 6.3 三平台打包与发布
- Tauri 2 本地构建（遵守"编译本地完成"约束）：Windows（.exe/.zip）、macOS（Apple Silicon/Intel .dmg）、Linux（.AppImage/.deb/.rpm）。
- 代码签名：macOS 公证 + Windows 签名需开发者证书——**待评估的成本项**（未签名版本可先发布，系统会有提示）。
- 发布渠道：本站下载区 + GitHub Releases（Oxelia51 仓或其子仓）。下载方式与适用场景见 §4.1 表格。
- **大版本更新检测**：应用内检查新版本 + 自动获取更新日志（§4.2）。🚧

### 6.4 P3 验收清单
- [ ] 三平台安装包产出并可下载
- [ ] 本地代理 + SQLite 落账跑通（改环境变量 → 本地记账 → 仪表盘可见）

- [ ] 应用内版本检测与更新日志展示

### 6.5 P3 实施计划（2026-08-08 定稿，已确认）

**代码载体**：`desktop/` 放 **Oxelia51 仓**（Go sidecar 源码 proxy-gateway 与发布主仓均在该仓，符合 §6.3「发布渠道 = Oxelia51 仓或其子仓」）。

```
Oxelia51/desktop/
├─ src-tauri/      Tauri 2 Rust 壳：窗口、侧车进程托管、系统通知
├─ ui/             React + Vite 桌面 UI（抽取 oxelia51 --ox-* 设计 token，双主题）
└─ sidecar/        本地模式 Go 网关（复用 proxy-gateway，见 §6.6）
```

**P3.0 前置**：本机安装 Rust toolchain（rustup stable，Tauri 必需）；确认桌面代码放 Oxelia51 仓。

**P3.1 核心闭环**（先打通「改环境变量 → 本地记账 → 仪表盘可见」）：
- `proxy-gateway/internal/recorder/sqlite.go`：新 `SQLiteWriter` 实现现有 `BatchWriter` 接口，批量 `INSERT` 本地 SQLite（`modernc.org/sqlite` 纯 Go 无 cgo，跨平台静态编译）。
- `cmd/proxy/main.go` 加 `LOCAL_MODE=true` 分支：recorder=SQLiteWriter、鉴权关闭、限流放宽、**默认端口 17800**（设置页可改）。
- sidecar 暴露**本地只读统计 HTTP 接口**（复用 `internal/stats/`：`/api/overview`、`/api/byModel` 等），UI 走 fetch——避免两进程并发写 SQLite，语义与云侧一致。Tauri 壳只负责拉起/停止 sidecar。
- Tauri 壳 + Vite React 单屏「总览」最小版。验收：Claude Code/Cursor 指 `http://localhost:17800` → 本地落账 → UI 可见数字。

**P3.2 五屏 UI**：总览全量 + 项目（Cursor 式：名称+本地文件夹引用）+ 会话（列表/详情，`session_id`）+ 告警（本地预算阈值 + 系统通知）+ 设置（端口/定价/主题）。

**P3.3 打包发布**：Windows .exe/.zip 本地构建；macOS .dmg / Linux .deb/.rpm/.AppImage 走 GitHub Actions 矩阵 runner；下载区上真实下载链接 + 应用内版本检测（大版本更新自动获取接通）。未签名版本可先发布（Mac/Windows 有提示），签名成本届时评估。

### 6.6 本地 SQLite 语义（与云侧共享，P4 同步天然对齐）

| 表 | 用途 | 字段来源 |
|---|---|---|
| `token_events` | 每次代理请求一笔 token 记录 | 复用 `adapter.TokenRecord`：EventID / ProjectID / SessionID / Provider / Model / PromptTokens / CompletionTokens / TotalTokens / DurationMs / Timestamp / APIKeyHash |
| `summaries` | 日/模型/项目汇总（查询提速） | 由 token_events 聚合 |
| `settings` | 端口 / 模型定价 / 主题 / 同步状态 | 配置 |

> 与云侧 CH `token_events` 共用同一语义模型（§5.4 维度：纵/横/时）；「空」维度（来源工具/设备）本地同样标注数据源不支持。
